# FlowHub 技术方案说明

版本：`v0.1.0`  
更新时间：`2026-03-15`

## 1. 技术架构概述

FlowHub 当前采用分层架构：

- OpenClaw 负责聊天入口和会话上下文
- OpenClaw 插件负责把聊天命令转成 FlowHub API 调用
- FlowHub Backend 负责 Skill 检索、Planner、Workflow 持久化和确认流程
- Client Runtime 负责工作流执行和 telemetry 回传

架构示意：

```text
OpenClaw Chat
  -> flowhub-openclaw plugin
  -> FlowHub Backend API
  -> SQLite / Planner / Skill Index
  -> Client Runtime
```

## 4. 关键业务流程

### 4.1 命令规划流程

1. 接收自然语言命令。
2. 提取 goal、targets、output_format、execution_mode。
3. 检索 `skills` 表中的已审核 Skill。
4. 根据本地规则或 AI 结果组合 workflow。
5. 保存 workflow 记录。
6. 保存 run_request 记录。
7. 返回：
   - `workflow_spec`
   - `assistant_response`
   - `selected_skills`
   - `communication_preview`

### 4.2 用户确认流程

1. 用户明确确认。
2. 调用 `POST /api/v1/run-requests/{id}/confirm`。
3. 系统读取已保存 workflow。
4. 系统生成确认后的 communication payload。
5. request 状态更新为 `queued`。

### 4.3 执行回传流程

1. Runtime 读取 workflow spec。
2. 执行节点。
3. 调用 `POST /api/v1/telemetry/events`。
4. 后端写入 telemetry_events。

## 5. Planner 设计

Planner 代码入口：

- `backend/app/services/planner_engine.py`

当前策略：

- 先对用户命令做 token 化
- 把目标地址和附加说明也纳入 token
- 从本地 Skill 索引中做匹配
- 本地优先挑选“collector + presenter”组合
- 若启用 AI，则将候选 Skill 提交给模型进行二次规划

本地规则的优点：

- 可控
- 不依赖外部模型
- 失败时仍可生成 fallback workflow

AI 规划的优点：

- 能对候选 Skill 做更细粒度排序
- 能生成更自然的工作流说明和步骤说明

## 6. AI 接入设计

AI 接入代码：

- `backend/app/services/planner_ai.py`

当前采用 OpenAI 兼容协议：

```text
POST {PLANNER_AI_BASE_URL}/chat/completions
```

默认实现值：

```text
https://api.openai.com/v1/chat/completions
```

必要配置：

- `PLANNER_AI_ENABLED`
- `PLANNER_AI_BASE_URL`
- `PLANNER_AI_MODEL`
- `PLANNER_AI_API_KEY`

回退机制：

- 任何模型配置缺失、请求失败或解析失败时，自动回退本地规则

## 7. Skill 索引设计

本地 Skill 索引是 Planner 的基础依赖。

来源：

- ClawHub 公共 Skill 目录

同步实现：

- `backend/app/services/clawhub_sync.py`
- `backend/app/services/skill_sync_scheduler.py`

同步特点：

- 分页抓取
- 幂等 upsert
- 缺失项归档
- 支持定时增量同步

## 8. 数据模型

核心表：

- `skills`
- `recipes`
- `workflows`
- `run_requests`
- `telemetry_events`

各表作用：

### skills

- 存本地 Skill 索引
- 来源包括手工录入和 ClawHub 同步

### recipes

- 存 workflow 模板
- 作为规则规划候选

### workflows

- 存最终生成的工作流定义

### run_requests

- 存用户发起的自然语言请求及确认前状态

### telemetry_events

- 存执行回传数据

## 9. OpenClaw 对接设计

OpenClaw 不直接调用网页，而是调用插件工具。

插件目录：

- `openclaw-plugin/`

工具：

- `flowhub_plan_command`
- `flowhub_confirm_request`

设计原则：

- 用户只停留在聊天窗口
- 不自动确认
- 不回显凭据明文
- 规划结果必须是用户可读文本

## 10. 部署逻辑

推荐部署顺序：

1. 启动 backend
2. 首次同步 Skill 索引
3. 配置 AI 参数（可选）
4. 部署 OpenClaw 插件
5. 配置 FlowHub agent
6. 联调聊天入口
7. 配置 Client Runtime
