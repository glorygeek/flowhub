# 10 首轮上线参数清单

版本：`v0.1.0`  
更新时间：`2026-03-15`

## 1. 文档目的

本文件用于首轮上线前逐项确认生产参数，避免：

- 本地配置误带入生产
- AI、Webhook、Registry 参数不完整
- 客户端与前后端地址不一致
- OpenClaw 对接时引用了错误入口

## 2. 上线前必须确认的参数

### 2.1 后端基础参数

这些参数是后端启动的最小集合：

```env
APP_NAME=FlowHub API
API_V1_PREFIX=/api/v1
DATABASE_URL=
FLOWHUB_API_KEY=
```

确认要求：

- `DATABASE_URL` 必须改为生产库路径或生产数据库连接串
- `FLOWHUB_API_KEY` 必须替换掉默认开发值

### 2.2 服务访问地址

```env
BACKEND_PORT=8000
FRONTEND_PORT=3000
FLOWHUB_API_BASE_URL=
```

确认要求：

- 宿主机端口不能与现有服务冲突
- `FLOWHUB_API_BASE_URL` 必须改为生产实际地址
- 如果前端走服务端代理，仍要保证前端容器内能访问后端容器

推荐示例：

```env
FLOWHUB_API_BASE_URL=https://flowhub.example.com/api/v1
```

### 2.3 ClawHub Registry 参数

```env
CLAWHUB_REGISTRY_URL=https://clawhub.ai
CLAWHUB_SYNC_ENABLED=true
CLAWHUB_SYNC_ON_STARTUP=false
CLAWHUB_SYNC_CRON=0 3 * * *
CLAWHUB_SYNC_TIMEZONE=Asia/Shanghai
CLAWHUB_SYNC_PAGE_SIZE=100
CLAWHUB_SYNC_TIMEOUT_SECONDS=20
CLAWHUB_SYNC_MAX_RETRIES=8
SKILL_SEARCH_REMOTE_ENABLED=true
SKILL_SEARCH_DEFAULT_LIMIT=24
```

确认要求：

- 首轮上线建议保留官方 Registry 地址
- 同步任务时间应避开业务高峰
- 如果部署区在中国大陆，需确认外网连通性与限流影响

### 2.4 AI 生产参数

统一 AI 网关现在使用 `AI_*` 变量。

```env
AI_ENABLED=true
AI_BASE_URL=
AI_MODEL=
AI_API_KEY=
AI_TIMEOUT_SECONDS=30
AI_DEFAULT_TEMPERATURE=0.2
AI_THINKING_ENABLED=
```

确认要求：

- `AI_ENABLED` 生产应明确设为 `true` 或 `false`，不能依赖默认值
- `AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY` 必须完整成组
- 若使用 DeepSeek，应明确模型和 thinking 模式

DeepSeek 推荐示例：

```env
AI_ENABLED=true
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-chat
AI_API_KEY=your-production-key
AI_TIMEOUT_SECONDS=30
AI_DEFAULT_TEMPERATURE=0.2
AI_THINKING_ENABLED=true
```

### 2.5 Webhook 告警参数

```env
AUDIT_ALERT_WEBHOOK_ENABLED=false
AUDIT_ALERT_WEBHOOK_URL=
AUDIT_ALERT_WEBHOOK_DESTINATIONS_JSON=[]
AUDIT_ALERT_WEBHOOK_ROUTE_RULES_JSON=[]
AUDIT_ALERT_WEBHOOK_TIMEZONE=UTC
AUDIT_ALERT_WEBHOOK_TIMEOUT_SECONDS=5
AUDIT_ALERT_WEBHOOK_MAX_RETRIES=2
AUDIT_ALERT_WEBHOOK_RETRY_BACKOFF_SECONDS=1
AUDIT_ALERT_WEBHOOK_RESPONSE_PREVIEW_CHARS=800
```

确认要求：

- 如果启用告警，至少要有一个可达 webhook 目标
- `ROUTE_RULES_JSON` 需要和实际运营分组匹配
- `TIMEZONE` 应与值班时区一致

### 2.6 CORS 参数

```env
CORS_ALLOW_ORIGINS=
CORS_ALLOW_ORIGIN_REGEX=
CORS_ALLOW_METHODS=["*"]
CORS_ALLOW_HEADERS=["*"]
CORS_ALLOW_CREDENTIALS=false
```

确认要求：

- 生产不要保留只面向 localhost 的默认 origin
- 前端域名、OpenClaw 调用域名、内部控制台域名要全部列入允许范围

## 3. 客户端参数

客户端侧至少要确认这些参数：

```env
FLOWHUB_API_BASE_URL=
FLOWHUB_API_KEY=
CLIENT_AI_ENABLED=
CLIENT_AI_BASE_URL=
CLIENT_AI_MODEL=
CLIENT_AI_API_KEY=
CLIENT_TOOL_SANDBOX_ENABLED=true
CLIENT_TOOL_ALLOWED_HOSTS=
CLIENT_TOOL_MANIFEST_PATH=
CLIENT_TOOL_MANIFEST_ALLOWED_SIGNERS=
CLIENT_TOOL_MANIFEST_ALLOWED_FINGERPRINTS=
CLIENT_TOOL_MANIFEST_ALLOWED_RELEASE_BATCHES=
CLIENT_TOOL_MANIFEST_CURRENT_RELEASE_BATCH=
```

确认要求：

- 客户端 API 地址必须指向正式 FlowHub 后端
- 客户端 AI Key 与服务端 AI Key 要明确分开管理
- Tool manifest 的 signer、fingerprint、release batch 必须和正式发布清单一致

## 4. OpenClaw 对接参数

首轮上线前必须确认：

- OpenClaw 插件安装目录
- `flowhub-orchestrator` 是否为主调度 Skill
- Bot 实际调用的 FlowHub API 地址
- Bot 所属工作区与会话持久化策略

如果 OpenClaw 与 FlowHub 不在同一主机或网络，需要明确：

- FlowHub 后端的可访问公网或内网地址
- API Key 的安全分发方式
- 是否需要额外反向代理

## 6. 首轮上线确认顺序

建议按以下顺序确认：

1. 后端数据库和 API Key
2. 前端访问地址和反向代理
3. AI 生产账号与模型
4. Registry 联通性和定时同步
5. Webhook 告警
6. 客户端 AI、sandbox、manifest
7. OpenClaw 插件和 Bot 入口

## 7. 上线后第一时间核验项

上线后建议立刻验证：

1. `GET /health`
2. `POST /api/v1/ai/chat`
3. `GET /api/v1/skills/search?q=stock`
4. `POST /api/v1/run-requests/`
5. `POST /api/v1/run-requests/{id}/confirm`
6. `/runs` 页面是否能看到 telemetry
7. Webhook 告警是否能收到测试事件

## 8. 当前建议结论

首轮上线最容易出问题的不是代码，而是参数不一致。

因此建议先把本文件逐项填实，再进行正式 tag 和生产部署。
