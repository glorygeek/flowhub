# FlowHub 发布前检查清单

版本：`v0.1.0`  
更新时间：`2026-03-15`

## 1. 用途

本清单用于正式交付、环境切换或首次发布前的最后检查。

目标不是重复开发测试，而是确认：

- 当前仓库状态可解释
- 核心链路可运行
- 运行配置已落位
- 交付文档与代码状态一致

## 2. 仓库检查

### 2.1 工作区状态

检查命令：

```bash
git status --short
```

通过标准：

- 所有改动都可解释
- 不存在无意义残留文件
- 拟发布内容与未发布内容已区分

说明：

- 当前仓库尚未形成稳定发布基线时，`git status` 可能显示大量未纳入版本控制的文件
- 这不是运行阻塞，但会影响正式交付追踪

### 2.2 文档状态

检查项：

- `README.md`
- `docs/delivery/README.md`
- `docs/delivery/05-测试验收清单.md`
- `docs/delivery/06-后续任务清单.md`

通过标准：

- 日期与当前交付状态一致
- 测试结果与最近一次回归一致
- “未完成项”描述的是运营/发布边界，而不是已知代码故障

## 3. 配置检查

### 3.1 Backend

检查文件：

- `backend/.env`

至少确认：

- `DATABASE_URL`
- `FLOWHUB_API_KEY`
- `AI_ENABLED`
- `AI_BASE_URL`
- `AI_MODEL`
- `AI_API_KEY`

### 3.2 Frontend

检查项：

- 服务端代理使用内部 API 路径
- 不向浏览器暴露后端管理密钥

通过标准：

- 不依赖 `NEXT_PUBLIC_API_KEY`
- `localhost` 和容器内地址配置一致

### 3.3 Client

检查文件：

- `client/.env`
- `client/tool-manifest*.json`

至少确认：

- `CLIENT_TOOL_MANIFEST_PATH`
- `CLIENT_TOOL_MANIFEST_ALLOWED_SIGNERS`
- `CLIENT_TOOL_MANIFEST_ALLOWED_FINGERPRINTS`
- `CLIENT_TOOL_MANIFEST_ALLOWED_RELEASE_BATCHES`
- `CLIENT_TOOL_MANIFEST_CURRENT_RELEASE_BATCH`
- `CLIENT_TOOL_MANIFEST_PREVIOUS_RELEASE_BATCHES`
- `CLIENT_TOOL_MANIFEST_PREVIOUS_BATCH_GRACE_DAYS`

### 3.4 OpenClaw

检查项：

- `openclaw-plugin/openclaw.plugin.json`
- `openclaw-plugin/index.js`
- `openclaw-plugin/skills/flowhub-orchestrator/`

通过标准：

- 插件入口完整
- 主调度 Skill 指向 `flowhub-orchestrator`

## 4. 核心验证命令

### 4.1 Backend

```bash
python3 -m pytest backend/tests -q
```

当前参考结果：

- `45 passed`

### 4.2 Frontend

```bash
cd frontend
npm run lint
npm run build
```

通过标准：

- lint 通过
- build 通过

### 4.3 Client

```bash
cd client
npm run typecheck
npm run build
```

通过标准：

- TypeScript 检查通过
- 静态构建通过

### 4.4 OpenClaw Plugin

```bash
npm exec -- node --check ./openclaw-plugin/index.js
```

通过标准：

- 插件入口语法检查通过

## 5. 环境联调检查

### 5.1 Backend 健康检查

```bash
curl http://127.0.0.1:8000/health
```

### 5.2 Frontend 代理检查

检查项：

- 首页可打开
- `/runs`
- `/skills`
- `/operations`

### 5.3 对话链路检查

最小验证：

- 非需求消息返回使用方法
- 有效需求可生成 workflow
- 确认后 request 可进入 `queued`

## 6. 当前不作为阻塞项的边界

以下项目仍需目标环境落实，但不视为当前仓库的代码阻塞：

- 外部 AI 生产账号、限额、成本控制
- Client 安装包签名与正式分发
- OpenClaw 目标环境部署
- 多租户与生产调度治理

## 7. 发布建议

发布前建议按这个顺序执行：

1. 完成配置检查
2. 跑完整体验证命令
3. 再做一次 `git status --short`
4. 产出发布说明或基线提交
5. 最后再切换到目标环境部署
