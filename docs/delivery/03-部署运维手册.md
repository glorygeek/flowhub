# FlowHub 部署运维手册

版本：`v0.1.0`  
更新时间：`2026-03-15`

## 1. 部署目标

本手册用于指导：

- 本地部署
- 测试环境部署
- OpenClaw 联调
- 日常运维

## 2. 运行组件

当前项目涉及以下组件：

- FlowHub Backend
- FlowHub Frontend
- FlowHub Client Runtime
- OpenClaw Plugin

## 3. 环境要求

### 3.1 Backend

- Python 3.11+
- pip

### 3.2 Frontend

- Node.js 20+
- npm

### 3.3 Client

- Node.js
- Tauri 运行条件
- Rust toolchain (`cargo`, `rustc`)
- Windows bundling 依赖会在首次 `tauri build` 时自动拉取 WiX / NSIS

### 3.4 OpenClaw

- 已可用的 OpenClaw 环境
- 可安装本地插件

## 4. 目录与关键文件

- 后端环境变量：`backend/.env`
- 后端示例变量：`backend/.env.example`
- 根目录示例变量：`.env.example`
- 数据库文件：`backend/data/flowhub.db`
- OpenClaw 插件：`openclaw-plugin/`

## 5. 后端部署

### 5.1 安装依赖

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 5.2 配置环境变量

建议从示例复制：

```bash
cp .env.example .env
```

关键变量：

```env
DATABASE_URL=sqlite:///./data/flowhub.db
FLOWHUB_API_KEY=dev-flowhub-key
FLOWHUB_API_BASE_URL=http://127.0.0.1:8000/api/v1
CLAWHUB_REGISTRY_URL=https://clawhub.ai
CLAWHUB_SYNC_ENABLED=true
CLAWHUB_SYNC_CRON=0 3 * * *
CLAWHUB_SYNC_TIMEZONE=Asia/Shanghai
AI_ENABLED=true
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-chat
AI_API_KEY=
AI_THINKING_ENABLED=true
```

说明：

- 统一 AI 网关优先读取 `AI_*` 配置。
- `PLANNER_AI_*` 仅作为兼容旧配置的可选项保留，不再作为推荐主入口。

### 5.3 启动后端

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 5.4 健康检查

```bash
curl http://127.0.0.1:8000/health
```

## 6. Skill 索引同步

### 6.1 首次同步

```bash
cd backend
python scripts/sync_clawhub_skills.py
```

### 6.2 强制全量刷新

```bash
python scripts/sync_clawhub_skills.py --full-refresh
```

### 6.3 API 方式触发

```bash
curl -X POST \
  -H "X-API-Key: dev-flowhub-key" \
  "http://127.0.0.1:8000/api/v1/skills/sync/clawhub?full_refresh=true"
```

### 6.4 定时同步

后端启动时会自动加载 APScheduler。

控制参数：

- `CLAWHUB_SYNC_ENABLED`
- `CLAWHUB_SYNC_CRON`
- `CLAWHUB_SYNC_TIMEZONE`

## 8. Client Runtime

### 8.1 安装依赖

```bash
cd client
npm install
```

### 8.2 类型检查

```bash
npm run typecheck
```

### 8.2.1 安装 Rust 工具链

首次在 Windows 环境构建 Tauri 客户端前，执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\codex-scripts\install_rust_toolchain.ps1
```

该脚本会安装 `rustup`、`cargo`、`rustc`，并把 Cargo bin 目录加入用户 PATH。

### 8.3 执行示例 workflow

```bash
npm run run-workflow -- --spec ./sample-workflow.json
```

### 8.4 执行 plan bundle + 客户端 AI

```bash
npm run run-plan
```

客户端会：

- 拉取官方 Skill 元数据
- 在 `429` 或网络失败时回退本地缓存
- 输出 resolved workflow 文件
- 优先使用客户端 OpenAI 兼容模型执行节点
- 调用失败时自动回退模拟执行

客户端可在 `client/.env` 中配置 `CLIENT_AI_*`；如果缺失，当前仓库运行时也会回退读取 `backend/.env` 的 AI 配置做本地联调。

### 8.5 打包产物

```bash
npm run tauri:build
```

当前实测产物位置：

- `client/src-tauri/target/release/flowhub-client.exe`
- `client/src-tauri/target/release/bundle/msi/FlowHub Client_0.1.0_x64_en-US.msi`
- `client/src-tauri/target/release/bundle/nsis/FlowHub Client_0.1.0_x64-setup.exe`

## 10. AI 模型配置

如果需要启用 AI 规划：

```env
PLANNER_AI_ENABLED=true
PLANNER_AI_BASE_URL=https://api.openai.com/v1
PLANNER_AI_MODEL=gpt-4o-mini
PLANNER_AI_API_KEY=your-key
PLANNER_AI_TIMEOUT_SECONDS=30
PLANNER_AI_MAX_CANDIDATES=8
```

如果不配置，Planner 仍然可用，只是回退到本地规则。

容器部署注意：

- `backend/.env` 不再打进 Docker 镜像
- 容器内 AI 是否启用，只由 `docker compose` 环境变量控制
- 如需在容器内启用 AI，请显式设置 `AI_ENABLED / AI_BASE_URL / AI_MODEL / AI_API_KEY`

## 11. 常用联调命令

### 创建一条 run request

```bash
curl -X POST \
  -H "Content-Type: application/json" \
  -H "X-API-Key: dev-flowhub-key" \
  http://127.0.0.1:8000/api/v1/run-requests/ \
  -d '{
    "goal": "抓取 incident API 的最新状态并输出 markdown 简报",
    "targets": [{"type": "api", "label": "Incident API", "value": "https://example.com/api/incidents/latest"}],
    "credentials": [],
    "output_format": "markdown",
    "execution_mode": "remote",
    "user_notes": "面向客户沟通"
  }'
```

### 确认一条 request

```bash
curl -X POST \
  -H "X-API-Key: dev-flowhub-key" \
  http://127.0.0.1:8000/api/v1/run-requests/1/confirm
```

## 13. 日常运维建议

建议关注以下方面：

- Skill 同步日志是否正常
- `skills` 表是否有数据
- AI 请求是否超时或失败
- Run Request 是否能正常从 `planned` 进入 `queued`
- telemetry 是否正常写入

## 14. 排障

### 14.1 后端启动失败

检查：

- `.env` 是否存在
- 数据库路径是否可写
- Python 依赖是否完整安装

### 14.2 Skill 同步失败

检查：

- ClawHub 接口是否可访问
- 是否遇到上游限流
- 超时和重试参数是否过小

### 14.3 OpenClaw 插件无法访问后端

检查：

- `apiBaseUrl` 是否可达
- API Key 是否正确
- 是否存在 WSL/Windows 网络隔离

### 14.4 AI 未生效

检查：

- `PLANNER_AI_ENABLED=true`
- `PLANNER_AI_MODEL` 是否配置
- `PLANNER_AI_API_KEY` 是否有效
- 外部模型接口是否可访问

## 15. WSL / Windows 特殊说明

如果：

- 后端运行在 WSL
- Node / OpenClaw 运行在 Windows

则可能无法直接通过 `127.0.0.1` 访问 WSL 服务。

此时应改用 WSL IP，例如：

```text
http://172.22.xx.xx:8000/api/v1
```

## 16. 交付后建议

建议交付后优先完成以下事项：

1. 在目标 OpenClaw 环境安装插件并完成 agent 绑定。
2. 完成一次真实聊天链路联调。
3. 完成首次 ClawHub Skill 索引全量同步。
4. 视需要配置真实 AI 模型。
5. 增加生产环境日志和告警。
