# FlowHub 产品交付说明

版本：`v0.1.0`  
更新时间：`2026-03-15`

## 1. 产品定义

FlowHub 是一个基于 OpenClaw 对话入口的自动化工作流规划平台。

它不要求用户自己理解 Skill、Workflow、节点、参数映射等技术概念，而是让用户在聊天窗口里直接发送一句命令，然后由系统完成：

- 需求理解
- Skill 检索
- Skill 组合
- 工作流生成
- 用户确认提示
- 后续执行准备

## 2. 核心价值

### 对用户

- 不需要学习 OpenClaw 的底层使用方式
- 不需要自己寻找 Skill
- 不需要自己配置工作流
- 可以在聊天对话中完成整个请求流程

### 对业务方

- 可以把 OpenClaw 生态能力封装成统一的聊天服务
- 可以将复杂自动化需求标准化为可确认、可执行的流程
- 可以降低普通用户使用自动化的门槛

### 对生态

- 让 OpenClaw 的 Skill 生态不再只服务开发者
- 把 Skill 能力转成面向终端用户的对话式服务

## 3. 用户使用方式

用户不需要登录 FlowHub 后台，也不需要打开单独表单页。

用户只需要在 OpenClaw 聊天窗口中输入一句命令，例如：

```text
帮我抓取这个 incident API 的最新状态，并生成一段发给客户的 markdown 简报
```

系统会在同一对话中返回：

- 本次需求会如何执行
- 系统选择了哪些 Skill
- 每个 Skill 做什么
- 最终输出格式
- 是否确认继续

用户确认后，系统再把请求推进到待执行状态。

## 4. 当前已交付的用户链路

### 第一步：用户发送命令

用户通过 OpenClaw bot 发出自然语言命令。

### 第二步：系统返回规划结果

FlowHub 会生成并返回：

- 工作流标题
- 工作流说明
- 命中的 Skill 列表
- Skill 简介
- 使用方式
- 确认提示

### 第三步：用户确认

用户在聊天中明确回复确认。

### 第四步：系统进入待执行状态

FlowHub 将对应请求状态推进为 `queued`，并返回可继续发送给用户的确认消息。

## 5. 当前支持的典型场景

### 数据抓取

- 网站抓取
- API 数据获取
- 结构化信息整理

### 信息整理

- 摘要生成
- markdown 报告输出
- 面向客户的可读说明

### 工作流编排

- 从多个 Skill 中挑选能力
- 自动拼接成顺序执行的 workflow

## 6. 当前交付的主要能力

### 6.1 Skill 索引同步

系统可定时从 ClawHub 公共目录同步 Skill 到本地索引库，用于后续组合。

### 6.2 自然语言工作流规划

系统能够把用户一句话命令转成可保存的 workflow。

### 6.3 用户确认前后的消息生成

系统不仅输出 workflow 结构，也会输出用户可读消息。

### 6.4 OpenClaw 对话桥接

系统已经可以通过 OpenClaw 插件在聊天中调用 FlowHub。

### 6.5 执行 telemetry 回传

工作流执行端可以回传执行结果，便于后续追踪。

## 7. 当前交付边界

以下能力属于当前系统边界，不应在交付时被误认为已完整上线：

- 真实生产级多租户权限系统
- 商业化计费系统
- 大规模任务调度平台
- 完整企业级监控与告警平台
- 正式发布版桌面客户端

## 8. 当前项目角色定位

FlowHub 当前定位是：

- 对话式自动化规划层
- Skill 索引与工作流组合层
- OpenClaw 聊天后的智能编排后端

它不是：

- 最终用户直接操作的主站产品
- 完整的任务执行调度中心
- 已完全生产化的多端 SaaS

## 9. 对客户的推荐话术

可以这样描述当前交付版本：

> FlowHub 当前版本已支持用户在 OpenClaw 聊天中通过自然语言发起自动化需求，系统会自动检索本地 Skill 索引并生成工作流方案，在用户确认后进入待执行状态，并保留后续执行与结果回传的接口能力。

## 10. 交付结论

从产品角度看，本次交付已经完成了核心闭环中的“对话输入 -> 技能组合 -> 工作流返回 -> 用户确认”这一主链路。

这意味着 FlowHub 已经从概念验证进入可联调、可演示、可继续扩展的阶段。
